Aurelia Sync

Provides the Aurelia music client with a resumable, ordered library sync protocol. This plugin only ever reads from Jellyfin; all of its own state lives in a separate database under the Jellyfin data directory.
When disabled, the status endpoint still reports why, and clients fall back to the standard Jellyfin API.

Retention

How long a completed snapshot is kept.
Losing a session never loses a client's checkpoint; the client simply opens a new one.
After this long without contact, a client's checkpoint is discarded and its next sync requires a fresh snapshot.

Delivery limits

How long a request waits for a snapshot that is still being built before answering with an empty segment. Kept well below the client's own timeout.
Zero disables the check. Only new snapshot builds are refused; clients already syncing keep working and can still acknowledge what they have committed.
Jellyfin's own response compression does not cover NDJSON, so this is applied by the streaming endpoint itself.

Snapshot materialisation

Items loaded from Jellyfin per batch. Larger batches are faster but use more memory on the server.
Set above zero to throttle snapshot builds on servers with slow storage.
Raising this lets several users' snapshots build at once, at the cost of more load on the media database.
A second device belonging to the same user reuses a snapshot this recent instead of building another one.
Logs additional protocol detail. Never logs tokens or payload contents.
When a client has been away long enough to fall outside the change journal, send only what changed plus a list of what still exists, rather than the whole library again. Turn off to always send a fresh catalog.
Skips a redundant parsing step when reading tracks from Jellyfin, taking roughly a third off the time to prepare a library. Verified to produce identical data; turn off if a future Jellyfin release ever makes that untrue.
